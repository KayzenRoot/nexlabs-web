# Contributing to NexLabs Web

Use the protected pull-request flow. Start from current `main`, preserve unrelated work, and do not force-push or bypass required checks.

For governed work:

1. read `AGENTS.md`, the Project Brain checkpoint and active Work Order;
2. resolve the exact Git base/head and HIVE preflight;
3. keep scope bound to the Work Order and Context Lock;
4. run application and governance validation locally;
5. update exact-head evidence and documentation;
6. open a PR and wait for `quality` and `Governance`;
7. merge only through protected flow after audit and explicit release authorization;
8. verify post-merge checks and promote the checkpoint only when evidence is accepted.

HIVE, GEF, provider credentials and machine-specific absolute paths must not be committed. The static website must remain operable without HIVE or GitHub.
